Levels built from goals: the game keeps ladders of rising goals along several scales, each level deals 3 of them, and once all 3 are met the player chooses to end the level or keep going. 1. Goal ladders: one list of rising targets per scale, kept like today's milestone ladder (10, 20, 50, 100, …). Candidate scales: crates delivered, one color delivered, big crates delivered, gremlins trapped, ex-gremlins, Things built or standing, construction feats (Belt run length, Bridge crossings, Spring/Cannon hops), turns without a lost crate. The player's place on each ladder carries from level to level, so every level asks for the next rung up.
2. Level start: the level opens with 3 goals drawn from different scales, each at the player's next rung on that scale, shown somewhere persistent (the tally? a goals panel?).
3. Completion: when all 3 are met, ask "End the level or continue?" Ending banks the result and starts a new level (new board? same board?). Continuing keeps the board running, maybe with fresh goals or a bonus ladder.

Open questions:
- Does this replace the endless milestone run or sit beside it as a mode?
- What does ending a level bank: a score, the turn count, unlocks that carry over (cards, board sizes), a star rating?
- Does continuing pay anything, and is there a reason to stop (risk, diminishing returns), or is it just more play?
- Is the draw seeded by Rando so it's reproducible? Can a player reroll or swap a goal?
- How do the card UNLOCKS map onto levels: per level, or by ladder rung?
- Where does progress across levels live (localStorage; per-viewer only)?
- Board size per level: does it grow or does the player pick it?

Needs an interview before it becomes tasks. Probably settle it together with goal-gen-tz9e.

More terrain types beyond today's water, plains, mountain and ice, each changing how pieces move or what can be built, so board layout poses new routing puzzles. Candidates:
- Sand / mud: sticky. A piece sliding or skidding onto it stops dead (the opposite of ice), and a bump doesn't carry across it. Maybe Belts can't be built on it.
- River / current: water that flows one way. A crate dropped in drifts a hex per tick downstream instead of sinking, until it reaches a bank or the edge. A free conveyor the player can use or has to bridge.
- Forest: blocks flights from landing (Springs and Rockets pass over it but can't come down on it), but ground movement is fine. Or the reverse: a low ceiling that stops Springs.
- Lava / pit: destroys whatever enters it, gremlins included (a natural trap), and nothing can be built on it. Lost crates count as lost.
- Rough / rubble: no building allowed, but pieces pass.
- Wind or tunnel pairs are more exotic; probably later.

Design notes: keep terrain data-driven in TERRAIN (artifacts.js), with flags like `slick`, `sticky`, `flow`, `noLand`, `kills`, plus the existing BUILDS_ON/`on` lists, so the movement rules read flags rather than kind checks. Generation (heightmap bands plus the ice carving) needs a placement rule for each new type, and the guaranteed land path from source to target still has to hold. Probably unlock the types by board size or milestone, so small boards stay readable. Each type needs a look (displayartifacts.js) and a hover name, and has to stay readable at zoom 1/2 (D-40), which ties into zoom-lod.

Open: how many types, and which first (one or two that create the most interesting decisions, then playtest)? Do they appear from the start, or arrive at milestones like colors do? Interaction with Slide (buildable ice) and Bridge (a Belt on water): what can each Thing be built on?

Needs an interview before it becomes tasks.

A leaderboard: compare runs, your own or other players'. The score already exists: the turn each milestone was reached (fewer is better), per board size.

Two very different sizes of this:
- Local (cheap, fits today's pure-client game): a personal best table in localStorage (wrapped in try/catch; it can come back empty). Best turn for each milestone on each board size, top N runs with date and seed, shown on the intro/New Game picker or a Records button. No server.
- Global (needs a backend; the game has none today): post runs to a server (yuwakisacloud? a Cloudflare Worker + D1/KV?) and show the top runs per board size and milestone. Real problems: cheating (the client is fully trusted; a mitigation is to submit the seed plus the full command log and replay it headless on the server, since the engine is deterministic and runs in Node — the State/Engine split already supports this); names and moderation; privacy (no emails, just a chosen handle).

Fairness: random boards differ a lot, so a global board is fairest on shared seeds — a daily seed (everyone plays the same board that day) or a fixed weekly seed per size. Ties into productize and level-goals (if levels exist, rank per level instead).

Open: local first, or straight to global? What's ranked (turns to milestone N, crates by turn T, ex-gremlins)? Daily seed or any seed? Needs an interview before it becomes tasks.
