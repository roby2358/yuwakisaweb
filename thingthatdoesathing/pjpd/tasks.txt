Split the randomness into a build seed (makes the board) and a run seed (plays it), and name the build seed with three words taken from a static word list, so a board can be shared and rebuilt ("frost-lantern-otter").

Today, newGame(seed, size) seeds the single global Rando once (generateMap calls Rando.seed), and the same stream goes on to place the first color, the starting crate and gremlins, the hand, and then every tick (spawns, wander, draws, openColor). So two players on the same seed get the same board only if they also play identically.

Designer's rule:
- Build seed: makes the starting board: the hex grid, terrain (heightmap and ice), the first source and target, and the first color. Decide and log whether the starting gremlins and the starting crate belong to build or run; default build, so the opening position is identical.
- Run seed: everything after the board is built: the hand, spawns, gremlin wandering, big-crate rolls, openColor, redraws. Rolled separately and randomly for each game, so the same three words give the same board but a different run. Store both in GameState (e.g. `buildSeed` and `runSeed`, replacing `seed`). The engine reseeds Rando with the run seed right after generation. Rando stays one global with `seed(n)`; no second instance needed unless that turns out cleaner (log it).
- Three words: a static list in artifacts.js (or its own words.js plain-script global, included in index.html and the test loader). Short, common, family-friendly, distinct-looking English words; no near-duplicates or homophones. Size it to a power of two, e.g. 1024 words (3 words = 30 bits) or 2048 (33 bits).
  - Direction: the words are the identity. Build seed = a hash of the normalized words (lowercase, trimmed, joined with '-'; a small stable string hash like FNV-1a, written in the engine/artifacts, no library). Rolling a new game picks 3 random words (with Math.random in the UI, like the seed today) and hashes them.
  - newGame takes the words (or the build seed) plus the size, and an optional run seed for tests and replays. All randomness stays reproducible from (words, size, runSeed). Validate: exactly three words, each on the list, or ok:false.
- Generation fallback (designer's call): if the board from build seed h doesn't generate (no source→target land path), try h+1, then h+2, and so on until one does (expected to be extremely rare). Each try reseeds Rando with that seed, so it's deterministic: the same words always land on the same board, and the words shown always rebuild the board you see. This replaces both the GEN_MAX_ATTEMPTS in-stream retry and the knownGoodSeed fallback; remove MAP_SIZES.knownGoodSeed and GEN_MAX_ATTEMPTS if nothing else uses them (no dead constants). Store the seed that actually generated if that's useful for debugging, but the words stay the identity. Add a sanity cap (e.g. 1000 tries, then throw) so a broken generator fails loudly instead of hanging.
- UI: show the three words for the current board somewhere unobtrusive (the HUD under Turn, or the help overlay) where they can be selected and copied. The New Game / intro size picker gets an optional "board words" field: blank = random; typed words = that board (an invalid entry shows a gentle inline message and doesn't start). The field mustn't swallow the picker's 1–4 hotkeys while focused; decide and log how keys behave in it.
- test/sim.js and tests that call newGame(seed, size) with integers: keep an integer path, newGame accepting a build seed directly, or update the callers. Decide and log; don't break `just cc-sim` reproducibility.
